# Feature: Keep the backup reviewer inside the PR checkout

**Branch:** security/sweep-2026-10-25
**Date:** 2026-10-25

## Summary
The backup reviewer's Claude can now read only the PR worktree, and its git commands can
no longer write files or read files outside it. CI actions are pinned to commit SHAs.

## Motivation
The reviewer gave Claude a bare `Read` and `git diff:*`. In a test, Claude read a file in
the home folder and `git diff --output=<path>` / `git log --output=<path>` wrote files
outside the worktree. Findings are posted to public PRs, so a prompt hidden in PR content
could leak secrets or overwrite a file such as `~/.zshrc`.

## What changed
- `Read`, `Grep`, `Glob` are allowed only under `./**` (the worktree).
- `Bash(git *--output*)` and `Bash(git *--no-index*)` are denied.
- git and ocr run in Claude Code's sandbox (`--settings`): reads under `~/` are denied
  except the worktree, this repo's cache clone and `.tools` (other cached repos stay
  hidden); `/Volumes/` is denied too; no network. Reason: `git diff
  <outside-file> /dev/null` reads outside the repo without `--no-index`.
- `GIT_CONFIG_GLOBAL=/dev/null` for Claude, because the sandbox hides `~/.gitconfig`.
- The script fetches the blobs both diffs need before Claude runs (the cache is a
  `blob:none` clone and the sandbox has no network). The prefetch runs from the cache with
  `--no-ext-diff --no-textconv`, so PR `.gitattributes` can't pick a diff program.
- Worktrees are checked out with `core.symlinks=false`.
- `selftest.yml`: `actions/checkout` and `actions/setup-python` pinned to SHAs,
  `persist-credentials: false`.
